## Product contract

With `multi_tenancy` enabled, **System is the default workspace for global users, not a catalog shared with every tenant.** There is one built-in workspace: name `system`, display name `System`, `is_system=true`. The migration inserts it and startup ensures it exists and syncs enabled system administrators. Ordinary tenant users are not automatically enrolled in System. See `internal/store/schema.sql:44–64`, `internal/store/seed.go` (`EnsureSystemWorkspace`), and `internal/app/app.go` (`openAdminStore`). Use its stable identity, not its display name or position in a list.

| Context                                       | Expected behavior                                                                                                                                                                                                                                                                                                                    |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| System workspace                              | HCL-defined providers, their models, and aliases belong **only** here. They remain file-managed and read-only in the management API. Global users with System access start here; selecting a tenant workspace does not copy System resources into it.                                                                                |
| Non-System personal or organization workspace | Starts with its own inventory, which can be empty. Authorized users create providers, models, aliases, and API keys **inside that workspace**. Neither System nor another workspace supplies default models, alias targets, or inheritance bases. A user with multiple memberships acts within the selected workspace and its roles. |
| Inference                                     | A DB-issued key acts only in its owning workspace, even if its creator is a system admin. A key's model list can narrow that scope, never widen it. HCL clients use System inventory in multi-tenant deployments. Customer traffic uses authenticated inference; browser login is not inference authentication.                      |
| Operator and file-only workflows              | System membership, workspace administration, and the global `is_admin` flag are distinct. The global operator dashboard keeps its existing authorization. With multi-tenancy off, the solo operator continues to configure everything in HCL without PostgreSQL.                                                                     |

This supersedes the earlier suggestion to share selected System models with tenants. No sharing feature, per-tenant copies of HCL defaults, endpoint rename, or new deployment mode is required. Keeping the existing globally unique public names is sufficient for this milestone; duplicate names per workspace would require a separate routing/schema decision.
